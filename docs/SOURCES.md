## Memória delta e gating

Songlin Yang, Jan Kautz e Ali Hatamizadeh, *Gated Delta Networks: Improving Mamba2 with
Delta Rule*, ICLR 2025, arXiv:2412.06464v3.
https://arxiv.org/abs/2412.06464v3
https://arxiv.org/html/2412.06464v3

A referência combina gating e atualizações delta e estuda arquiteturas híbridas com atenção
local. Nosso modelo é uma adaptação experimental simplificada: não implementa o algoritmo
paralelo de treino, escala, dados ou arquitetura completa do artigo. Resultados publicados
não validam automaticamente este código nem a versão ternária.

## Dispatch por CPU e funções especializadas

GCC, x86 Built-in Functions:
https://gcc.gnu.org/onlinedocs/gcc/x86-Built-in-Functions.html

GCC, x86 Function Attributes:
https://gcc.gnu.org/onlinedocs/gcc/x86-Function-Attributes.html

`__builtin_cpu_supports("avx2")` seleciona o kernel quando suportado; a função especializada
usa o atributo target, sem habilitar AVX2 globalmente para o executável. GCC/Clang x86 foram
exercitados no host; outras plataformas usam fallback e não foram certificadas aqui.

## Treinamento CPU opcional

PyTorch — instalação oficial:
https://pytorch.org/get-started/locally/

Escolha o sistema operacional e a plataforma de computação CPU no seletor. A versão do
ambiente usado nos experimentos é 2.10.0+cpu; isso não é uma afirmação de que seja a versão
mais recente. Python/PyTorch não são necessários para executar os binários nativos.

Não há chamada de API externa, download automático de modelo ou necessidade de token/chave.

## v0.4 additions (consulted 2026-09-25)

- PyTorch, quantization overview / mixing quantized and floating-point operations:
  https://pytorch.org/blog/introduction-to-quantization-on-pytorch/
- PyTorch, Quantization-Aware Training:
  https://pytorch.org/blog/quantization-aware-training/
- PyTorch per-channel fake quantization contract:
  https://docs.pytorch.org/docs/stable/generated/torch.fake_quantize_per_channel_affine.html

Selective/mixed quantization and QAT are established techniques. Our per-row INT8
STE implementation is custom, not the torchao production runtime. Training is still
FP32 simulation; native INT8 code uses FP32 activations/accumulation. External sources
motivate the experiment; no published quality/speed/energy numbers are attributed to
our implementation. All project numbers come from the included raw experiments.

## v0.5 — causal baseline and positional encoding (consulted 2026-09-25)

- RoFormer / Rotary Position Embedding, original paper:
  https://arxiv.org/abs/2104.09864
- PyTorch scaled dot-product causal attention contract:
  https://docs.pytorch.org/docs/2.14/generated/torch.nn.functional.scaled_dot_product_attention.html
- PyTorch per-channel fake quantization:
  https://docs.pytorch.org/docs/2.14/generated/torch.fake_quantize_per_channel_affine.html

This package implements explicit attention math, not an optimized SDPA kernel.
The installed training environment is PyTorch 2.10.0+cpu, not necessarily the latest
version of the documentation above. The Transformer is a one-block reference with
standard components, not a newly discovered architecture. Bits/byte here is derived
as summed next-byte NLL / (number of evaluated bytes * ln(2)). Neither perplexity
nor next-byte accuracy is evidence of a general assistant matching Claude.
