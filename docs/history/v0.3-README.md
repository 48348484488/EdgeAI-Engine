# EdgeAI Engine v0.3 — laboratório de IA em CPU

Engine C++17 com inferência neural nativa e ferramentas determinísticas. **É um
protótipo de pesquisa, não um assistente avançado nem uma demonstração de superioridade
sobre Claude ou outros modelos grandes.** Não requer GPU, Python, PyTorch, internet
ou chave de API para executar o programa C++.

Esta versão inclui código-fonte, modelo demonstrativo treinado de 24.102 parâmetros,
checkpoint, testes, comparações controladas e resultados brutos. O modelo de linguagem
foi treinado em um corpus minúsculo: sua saída ainda é repetitiva. O objetivo é validar
engine, treinamento, formato, equações e limitações, não apresentar esse modelo como produto.

## Executar

### Linux x86-64 — binários incluídos

Na pasta extraída:

```bash
chmod +x bin/linux-x86_64/*
./bin/linux-x86_64/edgeai_chat models/hybrid_tiny.edge --mode eco
```

Binários testados somente no Linux x86-64 deste laboratório. A dependência da versão
local de glibc/libstdc++ pode impedir execução em distribuições antigas; nesse caso,
compile no próprio computador. Não existe garantia de funcionar em qualquer PC.

### Compilar Linux/macOS

Requer CMake >= 3.16 e compilador C++17:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
./build/edgeai_chat models/hybrid_tiny.edge --mode eco
```

### Windows

Requer CMake e um compilador C++17 configurado, como MSVC. No terminal de desenvolvimento:

```bat
build_windows.bat
build\Release\edgeai_chat.exe models\hybrid_tiny.edge --mode eco
```

**Não há executável Windows incluído, e esta versão não foi testada no Windows/macOS.**
O caminho acima corresponde ao gerador Visual Studio; outros geradores podem usar `build\edgeai_chat.exe`.

### Comandos do programa

```text
253 * 719
-2^2
lembrar: o projeto usa kernels ternarios
buscar memoria: kernels
usuario: ola
assistente:
sair
```

Cálculos e memória textual não dependem do modelo. Perguntas abertas usam um modelo
experimental que ainda não responde bem. `token_score` é a probabilidade máxima de
um token, **não** a probabilidade de a resposta estar correta. Sem arquivo de modelo,
a engine disponibiliza ferramentas e um backend de desenvolvimento explicitamente identificado.

Modo de uma pergunta:

```bash
./build/edgeai_chat models/hybrid_tiny.edge --mode eco --memory :memory: --prompt "253 * 719"
./build/edgeai_inspect models/hybrid_tiny.edge
```

## O que mudou de fato

1. **Kernels:** implementação escalar de referência, LUT de pares e AVX2 com detecção
   em execução. O executável inteiro não é compilado com `-march=native`. Builds
   sem SIMD usam kernels portáveis. AVX2 especializado é habilitado em x86 GCC/Clang;
   outros compiladores/arquiteturas usam o caminho portável.
2. **Backend híbrido:** memória delta matricial, atenção local causal em buffer circular,
   gates aprendidos por token para esquecimento/escrita/mistura e FFN de pesos compartilhados.
   Projeções do núcleo são ternárias; embeddings, saída, gates e ativações continuam FP32.
3. **Correção/validação:** divergência de estado treino/inferência da v0.2 corrigida;
   verificações de testes não somem em Release; comparação de todos os logits entre
   Python e C++; leitura de modelos valida dimensões, truncamento, NaN e códigos reservados.

Os controles de memória são inspirados na regra delta com gating; esta implementação
**não é uma reprodução de RWKV, Mamba ou Gated DeltaNet**. Referências em `docs/SOURCES.md`.

## Limites importantes

- Estado de sequência limitado não significa memória perfeita ou ilimitada. Colisões,
  interferência e esquecimento continuam existindo.
- O modelo nativo conserva a profundidade treinada; o orçamento rejeita profundidades
  acima do permitido em vez de fingir que confiança softmax decide raciocínio correto.
- ECO/BALANCED/MAX limitam contexto a 2.048/8.192/16.384 bytes e profundidade máxima
  a 2/4/8. Não são modos de potência medidos. Inferência atual usa **uma thread**.
- Cada `ask` reinicia o estado neural; não há histórico conversacional automático.
- A memória textual herdada da v0.2 é arquivo de linhas carregado em RAM e busca lexical.
  Não é um RAG semântico, SQLite, mmap ou banco de tamanho ilimitado.
- Pesos são carregados em RAM. mmap, INT8 de ativações, NEON, especialistas, quantização
  seletiva e treinamento em escala **não estão implementados**.
- Benchmark de matriz não é benchmark de inteligência. Passos de byte não são tokens
  BPE nem respostas úteis por segundo. Tempo de execução não substitui medição de joules.

## Treinar e exportar

Treinamento opcional: Python + NumPy + PyTorch. Ambiente verificado: PyTorch 2.10.0+cpu.
Para instalação CPU-only, consulte `docs/SOURCES.md`; a inferência nativa não usa essas dependências.

```bash
python tools/train_hybrid.py data/tiny_corpus.txt --valid data/validation.txt --steps 160 --threads 1 --out models/hybrid_tiny.edge
python tools/verify_parity.py --binary build/edgeai_logits
python tests/test_gate_contract.py
```

Saídas: `.edge` para C++, `.pt` para validação/continuação de experimentos e `.training.json`.
O checkpoint é selecionado na validação, não no conjunto de teste de recuperação.
O treino de demonstração não é treino de instruções em escala. A atenção local do treino
usa uma matriz mascarada para sequências curtas; **não há algoritmo paralelo de treino da
memória delta**, que ainda percorre os tokens sequencialmente.

`tools/train_tiny.py` preserva o treinamento/exportação do modelo legado EDGEAI2.
A factory distingue o formato novo EDGEAI3 do legado pelo cabeçalho.

## Reproduzir as medições

```bash
python benchmarks/run_suite.py --build build
python benchmarks/quality_v03.py --steps 400 --seeds 11 22 33 --threads 1
python benchmarks/measure_energy.py --out results/energy.json -- ./build/edgeai_runtime_benchmark models/hybrid_tiny.edge 20000
```

A tarefa de qualidade é recuperação de associações sintéticas: seis registros que
codificam chave/valor, distrações, uma consulta e oito respostas possíveis. Todas as
variantes usam os mesmos lotes e teste independente, com três inicializações. Isso não
mede conversação, programação real ou inteligência geral. O Transformer tem aproximadamente
13% mais parâmetros; não se trata de igualdade exata de parâmetros ou FLOPs.

O teste piloto de gates fixos foi preservado em `results/quality_static.*`; sua reprodução
usa `benchmarks/archive/quality_static.py`. A comparação final usa outro conjunto de teste.
As funções de exportação arquivadas não representam o formato EDGEAI3 final.

```bash

cmake --build build-portable -j 2
```

Sanitizers requerem GCC/Clang compatível. Os logs fornecidos foram produzidos com Clang.

## Onde estão os resultados

- `BENCHMARK_RESULTS.md`: análise e tabelas, incluindo resultados negativos.
- `results/native.json`: tempos brutos por repetição, bytes, erro numérico, host.
- `results/quality.json`: resultados de todas as sementes/variantes.
- `results/parity.json`: comparação Python/C++ de todos os logits.
- `results/energy.json`: disponibilidade de sensores; joules nulos quando indisponíveis.
- `docs/FORMAT.md`: contrato do arquivo binário.
- `CHANGELOG.md` e `ROADMAP.md`: alterações reais e trabalho ainda não feito.
