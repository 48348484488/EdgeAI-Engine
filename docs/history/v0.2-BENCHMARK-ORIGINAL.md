# EdgeAI Engine v0.2 — Benchmark Results

Environment used here: Linux CPU VM, Release C++ build. Results are microbenchmarks and should be reproduced on target hardware before making energy/performance claims.

## 1. Existing deterministic engine path

`edgeai_benchmark`, 200,000 routed calculator operations:

- time: **0.423479 s**
- throughput: **472,279 ops/s**

This confirms v0.1's main design principle still works: do not activate a neural model when deterministic code solves the task exactly.

## 2. Native 2-bit ternary matrix vs equivalent FP32 matrix

256 x 256, 3,000 matvecs. Dense weights are set to the exact dequantized ternary values so both kernels compute the same mathematical matrix.

| Metric | Dense FP32 | Ternary 2-bit |
|---|---:|---:|
| Storage | 263,168 B | 18,432 B |
| Relative storage | 1.0x | 14.278x smaller |
| Runtime | 137.310 ms | 181.711 ms |
| Relative speed | 1.0x | 0.756x |
| Max absolute output error | — | 0.000 |

### Conclusion

The storage hypothesis is confirmed. The speed hypothesis is **not yet** confirmed: the first compact scalar decoder is slower than a dense loop that the C++ compiler can auto-vectorize efficiently. v0.3 should add architecture-aware SIMD lookup kernels and row alignment.

## 3. Full model storage

Bundled 32/64 demo configuration:

- parameters: 22,528
- current resident weights: 69,376 B
- hypothetical all-FP32 parameters: 90,112 B
- total-model compression: **1.299x**

Why only 1.3x? Embeddings and output head remain FP32. Hidden/core matrices receive the large compression; v0.3 must test INT8/low-bit embeddings and output head without destroying quality.

## 4. Train/export/inference integration

`tools/train_tiny.py` was run for 180 steps on `data/tiny_corpus.txt`:

- starting observed loss (step 18): 3.7358
- final observed loss (step 180): **1.8482**
- exported `models/trained_demo.edge`
- C++ model inspector loaded it successfully
- C++ `TernaryBackend` generated output from it successfully

The corpus/model are too tiny to evaluate language intelligence. This test only validates end-to-end compatibility.

## 5. Long-range retrieval quality gate

Synthetic task: remember 12 random symbols and reproduce them after a long gap. 250 training steps.

| Model | Parameters | Accuracy | Train steps/s |
|---|---:|---:|---:|
| EdgeAI v0.2 ternary recurrence | 20,466 | **1.46%** | 25.58 |
| 1-layer Transformer | 27,666 | **11.69%** | 180.62 |

Chance is roughly 1/64 ≈ 1.56%, so the current recurrent core is essentially at chance on this precise retrieval test. This is a **failed architecture test**, and it is useful: do not scale this exact recurrent core expecting frontier reasoning.

## Research decision from v0.2

Keep:

- hybrid deterministic routing;
- `.edge` format;
- native 2-bit ternary matrix storage;
- shared/reused reasoning weights;
- CPU-only native inference separation from training.

Replace/improve:

- simple recurrent long-term state;
- scalar packed ternary kernel;
- FP32 embedding/output storage.

Next candidate: strong sequence backbone (RWKV/SSM/Delta-style) + exact local attention scratchpad + low-bit CPU kernels.
