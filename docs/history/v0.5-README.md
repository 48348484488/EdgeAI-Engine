# EdgeAI Engine v0.5 — CPU, metas executáveis e comparação por custo

Engine experimental C++17 para inferência em CPU, ferramentas determinísticas e pesquisa
com modelos compactos. **Não é um assistente avançado e não foi demonstrado superior a
Claude.** O avanço desta versão é medir qualidade e custo com controles, em vez de insistir
numa arquitetura só por ela parecer promissora.

## O que foi entregue

Transformer causal nativo com janela circular/RoPE e INT8; híbrido anterior preservado;
formato EDGEAI5 e leitores EDGEAI2/3/4; corpus congelado por arquivo; 21 treinos de pesquisa;
avaliador nativo por byte; paridade Python/C++; medições de tamanho/CPU/RSS; executor de
metas sem interação. Resultados: **[BENCHMARK_RESULTS.md](BENCHMARK_RESULTS.md)**.
Metas executadas e pendentes: **[METAS.md](METAS.md)**.

A comparação com atualizações iguais favoreceu o híbrido na previsão de bytes, mas ele
custou muito mais CPU para treinar. Com orçamento de CPU igual, o Transformer INT8 teve
erro menor neste corpus. Por isso ele passa a ser a referência prática, não uma promessa
de arquitetura revolucionária. Modelos de todas as seeds estão disponíveis, sem selecionar
somente o melhor teste.

## Rodar a engine — Linux x86-64

```bash
chmod +x bin/linux-x86_64/*
./bin/linux-x86_64/edgeai_chat models/compute_v05/transformer_int8-seed11.edge --mode eco
```

Os binários foram testados no Linux x86-64 do laboratório. glibc/libstdc++ compatíveis
são necessárias; compilar no próprio computador evita depender das versões do host.
Não há garantia de funcionar em qualquer PC. **Não há executável Windows/Android incluído.**
A demonstração é um pequeno modelo de código/texto técnico, não um chatbot fluente.

Comandos:

```text
253 * 719
lembrar: o projeto mede qualidade e custo juntos
buscar memoria: custo
sair
```

Cálculo e busca lexical são determinísticos, não dependem da qualidade neural. Perguntas
abertas usam o modelo experimental e podem produzir texto sem sentido. Cada `ask` reinicia
o estado neural; memória textual persistente não é aprendizado dos pesos nem conversa
neural ilimitada. `token_score` é probabilidade do token, não chance de resposta correta.

## Compilar e testar C++ — sem Python na inferência

CMake >=3.16 e compilador C++17:

```bash
cmake -S . -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j 2
ctest --test-dir build --output-on-failure
./build/edgeai_inspect models/compute_v05/transformer_int8-seed11.edge
./build/edgeai_chat models/compute_v05/transformer_int8-seed11.edge --mode eco
```

O núcleo C++ não usa GPU, internet, API, Python ou PyTorch. AVX2 é selecionado quando
suportado; existe fallback portátil. Fallback testado no host moderno não certifica
hardware antigo. Windows: `build_windows.bat` em terminal de desenvolvimento com CMake e
C++17. Windows/macOS não foram executados nesta entrega; não há certificação dessas plataformas.

## Executar metas automaticamente — ferramentas de pesquisa

Ambiente testado: Python 3.13.5, PyTorch 2.10.0+cpu e NumPy 2.3.5. Além desses pacotes,
CMake/compilador. `requirements-training.txt` é opcional para desenvolvimento, não para
usar o binário. Escolha a distribuição CPU do PyTorch na fonte oficial indicada em
`docs/SOURCES.md`. O executor não instala pacotes nem usa rede automaticamente.

```bash
# Exibe comandos; não executa etapas.
python tools/run_goals.py --profile research --list

# Ciclo de validação pequeno: 2 modelos, 30 passos, uma seed.
python tools/run_goals.py --profile quick

# Ciclo de pesquisa: 15 treinos por atualizações + 6 por orçamento CPU.
python tools/run_goals.py --profile research
```

O perfil research executa 12 etapas, sem pedir aprovação entre elas: configuração,
compilação, testes C++, testes Python, paridade do Transformer, treino/avaliação por
atualizações, paridade dos checkpoints, benchmark nativo, treino por orçamento CPU,
paridade desse follow-up, seu benchmark e tentativa de leitura de energia.

Status e logs: `results/v05/goals-<perfil>/status.json`. Em erro, retorna código não zero e
indica o log; não continua silenciosamente com dados inválidos. Só reutiliza ensaios
completos do teste de atualizações quando configuração/código/dados/binário e hashes dos
artefatos conferem. Treino interrompido no meio reinicia a tentativa; não retoma o estado
do otimizador. O ensaio com orçamento de CPU é reexecutado para medir o hardware atual.
O script tem fim e limites; não é um serviço permanente nem trabalho contínuo do chat.

A execução pode sobrescrever resultados/modelos desse perfil. Faça uma cópia da pasta
antes de comparar máquinas ou modificar corpus/hiperparâmetros. Alterar os resultados JSON
não atualiza automaticamente a interpretação deste relatório de entrega.

## Reprodução por componente

```bash
python benchmarks/language_v05.py --steps 400 --seeds 11 22 33 --threads 1 --resume
python benchmarks/compute_budget_v05.py --cpu-seconds 12 --seeds 11 22 33
python tools/verify_trained.py
python tools/verify_trained.py --report results/v05/compute_budget.json --out results/v05/compute_trained_parity.json
python benchmarks/native_v05.py --out results/v05/native.json
python -m unittest discover -s tests -p 'test_*.py' -v
```

Para novas experiências com texto externo, o treino híbrido `tools/train_mixed.py` da
v0.4 permanece disponível. O benchmark v0.5 é deliberadamente fixado ao corpus fornecido,
com manifesto e hashes: não é um importador genérico de datasets.

## O que os resultados NÃO demonstram

Modelo inteiro INT8 de referência: 116.148 bytes, 62.112 parâmetros. Armazenamento menor
não implica inferência mais rápida: nesta escala o FP32 continuou mais rápido. Sem sensores
legíveis, energia permanece `null`. O corpus tem apenas 58.838 bytes de treino, gerados
principalmente durante o próprio projeto. Bits/byte e acerto do próximo byte não medem
inteligência geral, correção de programas, respostas úteis ou capacidade de seguir instruções.

Não há comparação com Opus, medição em PC fraco físico, mmap, MoE, LoRA, memória semântica,
ou treinamento inteiramente INT8. Há código, modelos minúsculos, controles e resultados
reproduzíveis para orientar a próxima etapa sem inventar progresso.

- `results/v05/`: resultados brutos, status e logs desta versão.
