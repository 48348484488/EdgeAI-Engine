# EdgeAI V27 — atomic recovery of V15 providers (2026-10-29)

## Change

Added `tools/edgeai_2048_v15_recovery.py` and `tests/test_edgeai_2048_v15_recovery.py`. The recovery driver invokes the existing source-blind `aarch64_multistage_batch.py` with the V15 stateful-printf lifter, then requires:

- Original stripped ELF SHA-256 `a3ca49d16ca6428291574ebd3f7c54153ef0913f8aa1eee4279408c3bf9d499b`.
- Exactly 19 C++ candidate files and matching address entries in `coverage.json`.
- Explicit `source_read=false`, `symbols_used=false`, and `compile_status=SUCCEEDED`.
- `edgeai_cpp_link_gate.py --strict-link` success with all 19 expected unmangled exports.
- SHA-256 manifest of each generated C++ file.

The driver stages its output in a temporary directory and publishes only after all checks succeed. It refuses to overwrite an existing destination and does not label host-native linkage as QEMU parity.

## Evidence obtained in this run

Six regression tests passed locally, covering the successful synthetic two-function case, ELF pin mismatch, missing native export, candidate-count mismatch, preservation of an existing output, and false source-blind provenance. These tests use a **synthetic generator fixture**, not the 19-function game reconstruction. The V26 ZIP's original 2048 ELF hash was independently checked and matched the pinned hash.

**The real 19-function regeneration was not completed in this run.** The local execution environment had the original ELF and V26 native link gate, but not the V15 generator's full set of imported lifter modules. Running the driver with that incomplete local tool directory correctly returned `RECOVERY BLOCKED` without publishing partial output.

## Reproduce in a complete checkout

```bash
python3 -m unittest discover -s tests -p 'test_edgeai_2048_v15_recovery.py' -v
python3 tools/edgeai_2048_v15_recovery.py /path/to/original-2048.elf \
  --destination /tmp/edgeai-2048-v15-recovered
```

The second command must be run in a checkout containing all `tools/aarch64_*.py` lifter modules and a working host C++ toolchain. If successful, the destination will contain `coverage.json`, `native_link.json`, the 19 C++ files and `bundle_manifest.json`.

**Coverage stays 19/23 historically validated ARM64 functions.** V27 adds recovery infrastructure and tests; it does not validate any new original function or reconstruct the full game.
